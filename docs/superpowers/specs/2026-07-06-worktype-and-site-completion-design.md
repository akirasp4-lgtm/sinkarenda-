# 作業区分の更新＋現場完了の運用改善 設計書

日付: 2026-07-06 ／ 承認: 利用者（チャットで承認済み）
対象: index.html / admin.html のみ（**GAS・スプレッドシート・過去データは一切触らない**）

## 背景（利用者要望）
1. 作業区分の「前乗り」を「移動」に変え、「置局」「事務所」を追加したい。
2. 終わった現場がプルダウンに出続ける。完了ボタンが「その予定の代表者か管理者」しか押せず、実際には誰も押さない→完了にならないのが原因。

## 決定事項
- 置局・事務所は前乗りと同じ扱い＝**工番なし・出面集計対象外**（GASは workType==='現場作業' しか特別扱いしないため、HTML変更だけで成立）。
- 完了の運用は3点セット全部やる（利用者選択）。

## ① 作業区分（index.html / admin.html）
- 登録・編集フォームの選択肢: `前乗り` → **`移動`**（🚗のまま）。`置局`（📡）と`事務所`（🏢）を追加。並び: …撤去品返却 → 移動 → 置局 → 事務所 → 倉庫作業…
- アイコン表 wtMap: `移動:🚗` `置局:📡` `事務所:🏢` を追加。**`前乗り:🚗` は消さない**（過去データ表示用）。
- 画面内ガイド文言も更新。
- 過去に「前乗り」で登録済みの予定はそのまま「前乗り」と表示（データ移行しない）。

## ② 現場完了の3点セット
1. **誰でも完了ボタン**（index.html のみ。admin は元々全員押せる）: `renderSiteCompletionRow_` の canMark 判定（isAdmin||代表者）を撤廃し全員に表示。確認ダイアログ・updatedBy記録・「進行中に戻す」は現状維持。
2. **60日ルール**（index.html / admin.html の `populateLocationSelect`）: 最終予定日から**60日以上**予定が無い現場は、プルダウン末尾の `<optgroup label="── 過去の現場 ──">` にまとめる（選択は可能・非破壊）。しきい値は定数 `STALE_DAYS=60`。検索絞り込み・最近使った順ソート・件数表示・編集中の現在値保持は現行ロジックを維持。
3. **admin に完了管理**（admin.html「現場別管理」タブ）: 既存のモードバー（現場で探す/人で探す/予定だけ）に4つ目「🏁 完了管理」を追加。内容＝全現場一覧（元請/現場名/最終予定日/状態バッジ/切替ボタン）＋現場名検索ボックス。進行中を上・最終予定日の新しい順。データ源は allJobsites ∪ allNippos の(元請,現場)ペア。切替は既存 `toggleSiteCompletion_`（action:'update_site_status'）を再利用し、完了後に一覧を再描画。

## 変えないもの
- gas.js / デプロイ / スプレッドシート／工番・集計ロジック／president.html／ratel-yakuin.html
- admin のメインタブ構成（switchTab の並び順依存に抵触しない。genba タブ内のモード追加のみ）

## 検証
- ローカル配信（.claude/launch.json「root preview」:5175）で index/admin を開き、①区分の選択肢と表示アイコン ②完了ボタンが誰でも見える ③60日超の現場が「過去の現場」グループに落ちる ④admin 完了管理の一覧・検索・切替 を確認。コンソールエラー0。
