# 向君への予定表カレンダー改修依頼

現在、予定表カレンダーについて

- グローライズ
- GRミツマ

で分かれています。

今回、グローライズ関東支店を立ち上げ、実質的にGRミツマを関東支店として使用する形になりました。

現状だと、

- 本社（グローライズ）と関東（GRミツマ）で同じ予定が重複する
- 片方に登録した予定をもう片方から確認できない
- 全体の予定を確認しにくい
- 一方で、今後は本社／関東支店別で売上や案件実績も見たい

という問題があります。

なので、予定表自体を単純に1つへ統合するのではなく、以下のような構成にできないか検討してください。

## 希望イメージ

### ① 予定データは1つの共通DBにする

各予定に

- 本社
- 関東支店
- 両方

などの「拠点／所属」を持たせる。

案件についても可能なら

- 案件名
- 拠点
- 担当者
- 顧客

などを紐付けられる形にする。

### ② 表示画面は切替できるようにする

- 本社予定
- 関東支店予定
- 全社予定

の3パターンを切り替えて見られるようにしたいです。

全社予定では、本社・関東を同じカレンダー上に表示し、どちらの予定か一目で分かるようにしてください。

### ③ 二重登録をなくす

本社・関東の両方に関係する予定でも、同じ予定を2回登録するのではなく、

「対象拠点：本社＋関東」

のように1件だけ登録して、両方の画面に表示される仕組みにしたいです。

### ④ 将来的な売上管理につなげる

今後、

- 本社売上
- 関東支店売上
- 全社売上

を分けて確認したいので、予定・案件・売上で同じ「拠点」区分を使える構造にしておいてほしいです。

特に重要なのは、

**会社名で分けるのではなく、「本社／関東支店」という管理区分を別で持たせること。**

GRミツマ＝関東支店として運用していても、法人と拠点の概念は分けて持っておいた方が後々使いやすいと思っています。

今ある仕組みを大きく壊さず、できるだけ入力を増やさずに実現できる案を考えてください。

他にもっと良いやり方があれば、この案に拘らず提案してください。

## 設計イメージ

### 予定表
共通予定DB  
→ 本社ビュー  
→ 関東支店ビュー  
→ 全社ビュー

### 案件・売上
共通案件DB  
→ 本社売上  
→ 関東支店売上  
→ 全社売上

### 管理項目
法人と拠点は別項目で持つ。

例：

- 法人：グローライズ
- 拠点：本社

または

- 法人：グローライズ
- 拠点：関東支店

など。

将来的にGRミツマ法人を使う案件があっても、

- 法人
- 拠点

を分けておけば、予定・案件・見積・売上・粗利を同じ軸で集計しやすくなるため、この形を希望します。
